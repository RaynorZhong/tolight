## 完整质量门

本机执行 `scripts/quality-gate.sh`，退出 **0**。完整脱敏输出见 [quality-gate.txt](quality-gate.txt)。

```text
fmt: passed
clippy --locked --workspace --all-targets --all-features -- -D warnings: passed
cargo test --locked --workspace --all-targets: 3 integration tests passed
cargo deny --locked check: advisories ok, bans ok, licenses ok, sources ok
node --test tests/web/app.test.mjs: 36 passed, 0 failed, 0 skipped
Python signing vectors: 6 passed
```

Rust 集成测试覆盖 CLI help、只读方法和缓存、HEAD/304、同长度改写 ETag、路径遍历和符号链接越界。Node 覆盖各分片边界直到历史耗尽、跨多个分片的增量读取、待合并新消息、立即撤回、回复预览、回退/重建与迟到旧响应、失败保留和重试、纯文本 DOM、无写入口、隐藏页暂停轮询以及键盘焦点回归。

Clippy 负例：临时给 core 加入 `Some(1_u8).unwrap()`，相同命令以 **101** 退出，原因 `clippy::unnecessary_literal_unwrap`，随后逐字节恢复原文件。证据见 [clippy-negative.txt](clippy-negative.txt)。这证明本地门禁拒绝警告，**不代表远程 CI 已拦截一次提交**。

Python 负例：仅在临时副本修改第一组期望签名的一个字符，检查器以 **1** 退出：`get-query: signature does not match`；正式 JSON 未改动。证据见 [signing-negative.txt](signing-negative.txt)。六组向量覆盖带查询 GET、JSON POST、非默认端口、显式默认端口、IPv6、IPv4 嵌入 IPv6。复算离线执行，不依赖真实身份或 Coordinator。

## HTTP 与 Caddy 验收

最终版本在 Rust loopback 预览和 Caddy 2.11.9 上均通过：

```text
PASS GET / / conditional 304
PASS GET /app.js / conditional 304
PASS GET /style.css / conditional 304
PASS GET /robots.txt / conditional 304
PASS GET /data/manifest.json / conditional 304
PASS GET /data/agents.json / conditional 304
PASS GET /data/chunks/000000000001-000000000200.json / conditional 304
PASS GET /data/chunks/000000000201-000000000400.json / conditional 304
PASS GET /data/chunks/000000000401-000000000600.json / conditional 304
PASS public schemas, allowlists and complete seq=1..500
PASS static origin has no participant endpoint
PASS static origin rejects POST
```

每个资源的类型、安全头、no-cache、强 ETag 和 304 都由脚本检查。Caddy 的版本/配置/源文件摘要、真实命令输出、同秒同长度 fsync+rename 的 mtime/ETag/内容和条件请求证据见 [caddy-spike.md](caddy-spike.md)。最后一次 Caddy 复验已采用键盘修复后的 app.js。

浏览器检查实际发现并修复了一个问题：聚焦历史按钮触发上滚，会被误认为自动加载历史；插入补偿又把聚焦按钮移出屏幕。现在聚焦期间不触发自动加载，手动激活保持视窗并在 busy/失败后恢复焦点，耗尽时聚焦原位置的状态文本。36 项测试包含这两个回归测试；以上键盘结果是修复后的复测。最终浏览器没有捕获到 error/warn，临时 viewport 已复原。
