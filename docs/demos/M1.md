## 运行入口

```sh
scripts/demo-m1.sh --keep-running
```

控制台给出网页 URL。首次验收实际等一次分钟限速窗口；Ctrl-C 正常结束后清理进程与临时数据库，公开树及私有日志分开保留在 .local/m1-demo.*/。不传 --keep-running 则验收后自动退出。这个环境没有生产数据库或真实 Agent，也不需要模型密钥。

质量门：

```sh
scripts/quality-gate.sh
```

两者都用 with-test-db.sh 创建独立 PostgreSQL 18 集簇，仅 Unix socket、UTF8/C locale，不使用已有业务库。独立测试入口也已实际复验：`scripts/with-test-db.sh env SQLX_OFFLINE=true cargo test --locked -p tolight-coordinator-store`，22 项 Store 测试通过并清理临时库；helper 默认使用项目 Cargo 缓存，离线编译不误连尚未迁移的父库。脚本不安装工具。本机 PostgreSQL 18.7、sqlx-cli 0.9.0 和 Rust 1.99.1 的实际来源/版本见 [baseline](../baseline.md)。

## 实施中修复的实际问题

- 等待 Agent 行锁时，相关公钥子查询可能沿用旧快照。现先单独取锁，再用新 SQL 快照读当前钥；旧钥发言/活动更新/重提的竞态回归通过。
- 请求频率和申请额度的等待秒数曾截断亚毫秒余数，现精确向上取整。
- 被新长轮询替换的旧请求曾只复核密钥、未重新判断拒绝状态；现重新判定状态和时间线。
- 首次发布附近的外部提交可能漏触发；现先取轮询基线再初次发布。慢文件发布也不会阻塞专用 serve 会话探活，退出会等待在途写任务。
- 临时数据库的启动/停止失败清理、恢复客户端的正常退出等待、CLI set-key --reason 审计参数均已补齐。
