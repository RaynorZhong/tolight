| 问题 | 影响与修复 | 对应任务/验收 |
|---|---|---|
| 旧suite的沙盒通过记录不能重新检查 | approve拒绝旧suite，但读取不再启动当前suite，待审身份永久卡住；失效旧通过结果并启动当前suite，保留历史run | Task17，A10/A13 |

| 状态查询、发言、读取与增量发布加载全部历史 | 长期运行每次请求/发布成本随完整历史增长；拆只读元数据、有界参与者读取和稀疏增量发布，保留同事务快照及event_id恢复屏障 | Task9/11/12，NFR-003，A9/A11/A12 |
| 换钥确认对象可被同名申请替换 | 确认后仅按agent_id更新，会把旧申请核实的钥交给新申请；按application_id/revision复核，过期确认零写入 | Task8/22，A14 |
| CLI漏显示当前公钥登记时间 | 申请登记时间不能代表换钥时间；投影并显示当前有效钥的登记时间，旧schema1控制快照保持可读 | Task8/22，A14/A15 |
| 源码检查/检出演练漏掉deploy | 合法部署源码被判私有路径或静默漏打包；统一允许deploy，同时保留私钥拒绝 | Task27，A2/A17 |
| Retry-After持久化向下取整 | 进程重启后最多提前近1秒重试；保留亚秒期限并从持久状态继续等待 | Task13，A11/A13 |
| 非JSON或未知错误码的400/413/422留在pending | 监督器重启会原样无限重发；按不可重试HTTP状态丢弃该pending，仍保留连接/5xx/429重试语义 | Task13/16，A11/A13 |
| Caddy 32KB实际只有32000字节 | 合法32001–32768字节请求被代理提前拒绝；改32KiB并验证实际代理边界 | Task16，A10/A19 |
| WAL sidecar写到一半后无法重试 | 同名WAL存在而metadata半截，归档器永久拒绝；metadata先同步临时文件再原子安装，仅对相同WAL修复中断sidecar | Task28，A15 |
| 告警/探针重叠执行覆盖状态 | 固定state.tmp与未串行的整轮检查会重复发送、覆盖counter基线；按state-file持有非阻塞文件锁，状态替换后同步目录 | Task21/29，A16 |
| 投递失败丢失观测或重发成功通知 | 通知前先持久化已观察的counter窗口，避免首发失败后服务重启把增量抹掉；每条成功投递后再单独持久化ack，失败项继续重试；外部投递和本地落盘间崩溃仍可能重复 | Task21/29，A16 |
| 任意新dump/sql文件被当成成功备份 | 改为仅认自有逻辑备份完成marker，使用created_at并核对文件头/大小等元数据，不再凭touch或文件名压住backup_stale | Task21/29，A15/A16 |
| 历史/回复分片失败不在下一轮重试 | 轮询只恢复“正常”状态，仍需用户重按；保存待重试请求，下一轮重试，回退/撤回取消旧请求并保持阅读位置和键盘焦点 | Task4，A7/A8 |
| 大量已加载历史触发JavaScript参数栈上限 | Math.min及replaceChildren的参数展开会抛RangeError，历史无法继续或显示；改迭代求最小值及DocumentFragment渲染，分别用超过131000事件的真实大小回归 | Task4，A7/A8 |
| 历史加载完成抢走已移开的焦点 | 等待期间读者已转向其他控件，完成仍强制聚焦历史按钮；只恢复仍属于该请求的焦点意图，回退和主动移焦均取消 | Task4，A8 |
| 两客户端演示未同步公共起点 | A先发言、B稍后获批时正确将其当历史而不回，演示可能永远停聊；等待接收方公共游标后再放行第一句，不放宽客户端不回历史原则 | Task13/14/23，A9/A13 |

另同步计划质量门：实际包含locked/offline构建与Python发布/验收/停源恢复测试；明确依赖下载/漏洞库更新和离线检查的网络边界。M4选定演练的私有摘要固定为accepted文件，后续测试只更新latest，不再让历史记录的具体耗时指向不断变化的报告。
